# ecoconcept.kg — сайт

Сайт инженерной компании EcoConcept (Бишкек): тепловые насосы и солнечные станции
под ключ. Next.js 16 (App Router) + Payload CMS 3 + Tailwind 4.

Это **снимок рабочей копии для внешней проверки**. Боевых ключей, закупочных цен
и внутренней базы знаний здесь нет — см. «Чего здесь нет».

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
```

Переменные окружения для просмотра и правки сайта **не нужны**. Проверено на
чистом клоне: `npm install` → `npm run dev` поднимает все страницы, `npm run build`
проходит без единого ключа.

Что при этом не работает и почему:

| Что | Без чего | Как ведёт себя |
|---|---|---|
| Цена «под ключ» в расчёте | `PURCHASE_PRICES` | `/api/estimate` отвечает `{"price":{"heat":null}}`, страница показывает комплект без суммы |
| Отправка формы заявки | `DATABASE_URI` | `/api/lead` отвечает `save_failed`: заявке некуда записаться |
| Передача заявки в CRM | `B24_WEBHOOK_URL` | заявка ложится только в базу сайта |
| Админка Payload `/admin` | `DATABASE_URI`, `PAYLOAD_SECRET` | не открывается |

Формат переменных — в `.env.example`. Если нужно проверять формы, поднимите
Postgres и укажите строку подключения:

```bash
docker run -d --name eco-pg -e POSTGRES_PASSWORD=pass -p 5432:5432 postgres:16
echo 'DATABASE_URI=postgres://postgres:pass@localhost:5432/postgres' >> .env.local
echo 'PAYLOAD_SECRET=любая-длинная-строка' >> .env.local
npm run dev
```

Схему таблиц Payload создаёт сам при первом запуске.

## Проверено на чистом клоне

Перед публикацией репозиторий клонирован в пустую папку и проверен:

- `npm install` — 526 пакетов, без ошибок;
- `npm run dev` — `/`, `/heat-pumps`, `/to-know`, `/calculator`, `/catalog/heat-pumps` отвечают 200;
- `npm run build` — проходит, все маршруты рендерятся;
- `/api/estimate` отвечает корректно и без закупочных цен.

## Как устроен код

```
src/app/(frontend)/        страницы, по файлу на маршрут
src/components/            секции; общее для продуктовых страниц — в components/product
src/content/               ВЕСЬ текст и числа сайта, по файлу на страницу
src/lib/estimate.ts        физика расчёта: теплопотери, COP, блочный тариф
src/lib/heating-compare.ts сравнение стоимости отопления: уголь, газ, электрокотёл, насос
src/lib/pricing.server.ts  розничная цена. Только сервер, данные — из переменной окружения
src/content/catalog.ts     СГЕНЕРИРОВАН скриптом из паспортов, руками не править
public/video/              ролик о работе насоса (58 с, с озвучкой)
```

Тексты никогда не живут в компонентах: правится `src/content/*`, вёрстка не трогается.

## Правила, по которым это сделано

Проверяющему полезно знать, что здесь считается ошибкой:

1. **Ни одного утверждения без числа или источника.** Каждая цифра — из паспортов
   каталога, тарифа Минэнерго или ресёрча рынка КР. Непроверенное на сайт не идёт,
   а недостающее помечается прямо на странице.
2. **Сравнения — таблицей, а не карточками с иконками.**
3. **Фотография объекта, а не рендер.** Своей съёмки пока нет, поэтому каждый чужой
   кадр помечен плашкой «Сток · заменить» или «ИИ-генерация» прямо на снимке.
4. **Один акцентный цвет, градиенты запрещены** (два отступления сделаны осознанно:
   тёмная секция «Как мы работаем» и блоки-предложения на главной).
5. **Движение только как отклик на действие.** Ничего не появляется при прокрутке,
   автокаруселей нет, видео не запускается само.
6. **Честность как приём.** На страницах есть места, где прямо сказано, что наше
   решение не подходит: дом без утепления, подведённый газ, дача на выходные,
   станция без батареи там, где свет не отключают.

Шкала скруглений: 4 px — метки, 12 px — мелкие элементы, 20 px — карточки,
32 px — крупные блоки. Кнопки — таблетки, форма задана в `globals.css`.

## Что проверить в первую очередь

- Расчёты в `src/lib/estimate.ts` и `src/lib/heating-compare.ts`: блочный тариф
  считается от полного счёта дома, а не от одного прибора — это легко сломать.
- Согласованность чисел между `src/content/*` и каталогом.
- Доступность: alt у содержательных изображений, один H1 на страницу, состояния фокуса.
- Мобильная вёрстка на 390 px: горизонтального перелива быть не должно.
- `pricing.server.ts` не должен попадать в клиентский бандл (импорт только из
  серверного кода).

## Чего здесь нет

- **Закупочных цен и формулы розницы** — они в переменной окружения `PURCHASE_PRICES`,
  в исходниках их нет.
- **Ключей**: вебхук CRM, строка подключения к базе, секрет Payload.
- **Внутренней базы знаний** компании: решений, прайсов, контрактов. `DESIGN.md` и
  `PRODUCT.md` — самодостаточные выжимки из неё; ссылки внутри них на `Projects/...`
  ведут в базу, которой в репозитории нет, и открывать их не нужно.
- **Истории коммитов** рабочего репозитория: это отдельный снимок.

## Известные ограничения

- Все фотографии — сток и ИИ-генерации, каждая помечена. Ждём свою съёмку.
- Розничных цен в карточках каталога нет: прайс не утверждён.
- Раздел `/projects` пуст намеренно — портфолио на чужих кадрах собирать не станем.
- Кыргызской версии нет, переключатель RU в шапке — заглушка.
- Часть данных ждёт заказчика и помечена на страницах: имя бригадира, города
  объектов, число выполненных объектов, мощность насоса при −15 и −25 °C.
